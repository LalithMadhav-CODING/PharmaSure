# Citation-Level Counterfactual Evidence Auditing (CCEA)

**Status:** implemented, tested, integrated. Version `1.0`.
**Code:** `src/audit.py` · **Tests:** `tests/test_audit.py`, `tests/test_api_integration.py`
**UI:** `frontend/src/components/EvidenceAudit.tsx`, shown inside each candidate card as
*"Evidence stability audit"*.

---

## 1. What this feature does

For each drug–disease candidate, PharmaSure already computes an **evidence score**
and lists supporting literature. That score is a summary: it does not tell a
researcher whether the number rests on several independent sources or is
dominated by one influential paper.

The audit answers a counterfactual question:

> **What happens to this candidate's evidence score and its position in the
> evidence ranking if one contributing study is removed?**

For every eligible candidate it reports the baseline score, the study units that
contribute, per-source influence, leave-one-study-out score and rank changes,
evidence direction where classifiable, and explicit warnings where the data
cannot support a conclusion.

### What it is not

- It is **not** a probability of efficacy, clinical success, or treatment benefit.
- **Stability is not truth.** A ranking that barely moves when a study is removed
  is not thereby correct, safe, or clinically effective. It means only that the
  current evidence set is not dominated by that one source.
- Absence of evidence in the indexed corpus is **not** evidence of ineffectiveness.
- A real PMID and a verbatim quotation do not prove the whole generated claim is
  correct.
- The direction labels are machine-generated by unvalidated rules and are **not**
  expert-adjudicated.

## 2. Baseline scoring — reused, never reimplemented

The audit calls the product's existing scorer, `retrieval.evidence_score`, for
every baseline and every counterfactual. There is deliberately no second
implementation that could drift.

```
S = 0.25·R + 0.35·P + 0.40·Q
```

| Component | Meaning in the live code |
|---|---|
| `R` relevance | **mean** `retrieval_score` (cosine similarity) across the candidate's matching passages |
| `P` support | `min(passage_count, 5) / 5` |
| `Q` study quality | **maximum** study-type weight across those passages |

Study-type weights: `clinical_trial` 1.0 · `cohort` 0.7 · `preclinical` 0.4 ·
`review` 0.3 · anything else 0.3.
Tiers: `≥0.70` Strong · `≥0.40` Moderate · otherwise Preliminary.

`score_passages()` normalises one edge case: `evidence_score` omits the
`breakdown` key when the passage list is empty, so the audit supplies a zeroed
breakdown to keep the response shape stable. The numeric result is unchanged.

### ⚠ Divergence from the build specification

The specification states that the support component `P` is **PMID-deduplicated**.
**It is not.** The live implementation counts *passages*:

```python
support_count = len(drug_passages)          # retrieval.py
support = min(support_count, 5) / 5.0
```

Consequences, both of which are pinned by tests:

- Two passages from one PMID give `P = 0.4`, not `0.2`.
- Removing one study unit normally changes `P` — so a leave-one-out delta is
  rarely exactly zero for small evidence sets.
- `P` saturates at five passages, so sets of six or more are insensitive to a
  single removal on the support component.

**This was deliberately left unchanged.** Silently altering `P` would change
every baseline score the product already publishes, which the specification
forbids. The correct fix is a separate, explicitly versioned scoring change with
its own validation — not a side effect of adding an audit. See
`test_support_counts_passages_not_distinct_pmids` and
`test_support_component_saturates_so_large_sets_are_less_removal_sensitive`.

### Evidence rank vs. the displayed rank

**These are different things and the UI shows both.**

- The **displayed rank** (`rank`) is the knowledge-graph candidate order — the
  EveryCure matrix score order. It is what the candidate card shows as `#1`, `#2`, …
- The **evidence rank** is computed by the audit: candidates ordered by
  `evidence_score` with a deterministic tie-break (higher score first, then the
  original knowledge-graph position).

The audit never presents an evidence-rank change as a change to the EveryCure
order. `ranking_scope` is `evidence_rank_over_retrieved_candidates` on every
response.

## 3. Study grouping and deduplication

**Policy (chosen, documented, applied consistently):**

1. Records sharing a **PMID** form one study unit — they are by definition the
   same publication.
2. Records with **no valid PMID** fall back to their own `source_id`, so they are
   never silently merged with an unrelated record.
3. Grouping is deterministic: groups are sorted by key and do not depend on
   input order or hash iteration order.

**Independence is reported as unverified, not assumed.** This corpus carries no
trial-registration IDs, author sets, or other metadata linking distinct PMIDs to
a single underlying study. Therefore:

- every unit is reported with `study_independence_status: "unknown"`;
- `study_independence_verified` is `false`;
- the audit emits an explicit warning;
- distinct PMIDs are treated as separate units **for sensitivity testing only**,
  and the documentation never claims they are independent experiments.

`grouping_method` is `pmid_only` (or `source_id_fallback`). Groups whose only
publication type is `review` are flagged `is_review: true` and warned about — a
narrative review summarises other work and is not an independent experiment.

## 4. Leave-one-independent-study-out

For each eligible unit `g`:

```python
remaining = [p for p in drug_passages if p.pmid not in g.pmids]
counterfactual_score = retrieval.evidence_score(remaining, drug_name)   # same function
```

Removal happens at the **study-unit** layer, so every passage belonging to that
PMID is removed together. No LLM call and no re-embedding occurs inside the loop —
the audit is pure deterministic recomputation over already-retrieved evidence.

### Sign conventions

| Quantity | Definition | Positive means |
|---|---|---|
| `score_delta` | `baseline_score − counterfactual_score` | removing the study **lowered** the score |
| `rank_delta` | `counterfactual_rank − baseline_rank` | the candidate moved **down** the ranking (a larger rank number is worse) |

Both conventions are stated in the UI beneath the table.

### Rank recalculation

Only the audited candidate's score changes; peer scores are held fixed, so the
**same candidate set** is re-ranked every time and ranks stay comparable. Ties
break on the candidate's original knowledge-graph position
(`score_desc_then_kg_order`).

### Explicit insufficient-data states

| Situation | `status` |
|---|---|
| No source records retrieved for the candidate | `not_auditable` (reason `no_source_records_retrieved`) |
| Exactly one study unit | `insufficient_independent_studies_for_stability_test` (reason `only_one_study_unit`) — **no robustness claim is made** |
| Some scenarios failed | `partial` (successful scenarios are retained) |
| All scenarios succeeded | `complete` |
| Audit layer raised | `audit_failed` |

A failure in one scenario never discards the others, and an audit failure never
removes the candidate result from the response.

## 5. Stability metrics

Reported per candidate: `eligible_study_count`, `successful_counterfactual_count`,
`failed_counterfactual_count`, `max_absolute_score_change`,
`mean_absolute_score_change`, `median_absolute_score_change`,
`max_rank_movement`, `rank_min`, `rank_max`, `rank_range`,
`source_with_max_score_influence`, `source_with_max_rank_influence`.

**Statistics are `null`, not `0`, when there are too few observations** — a zero
would be a fabricated measurement.

**Thresholds are experimental and live in one place** (`audit.STABILITY_CONFIG`):

```python
"single_source_score_delta": 0.05   # |Δ score| from one removal
"single_source_rank_delta": 2       # |Δ rank| from one removal
```

Exceeding either marks `single_source_dominated: true`. These are descriptive
labels only. There is deliberately **no "robustness probability"** — a normalized
index would imply a precision this method has not been validated to support.

## 6. Evidence direction

### How it works

A conservative, deterministic lexical classifier (`lexical_rules@1.0`) scans for
**explicit** statements only:

- **`null_finding`** — "no significant difference", "was not associated with",
  "failed to demonstrate", "ineffective", …
- **`contradictory`** — "worsened", "did not provide any benefit", "no superior to", …
- **`supportive`** — "improved", "reduced the risk/severity/duration", "was effective in", …
- otherwise **`not_classified`**

Precedence is null → contradictory → supportive: an explicit "no significant
difference" is a more specific signal than a generic efficacy verb nearby.

### Honesty rules enforced in code

- **Mentioning the drug is not supportive.** With no directional statement the
  label is `not_classified`.
- **Safety is not efficacy.** Risk/harm language ("associated with increased
  risk", "adverse events", "toxicity") is captured by a **separate**
  `safety_signal` field and is *never* folded into `contradictory`. A safety
  concern is not evidence against efficacy.
- **Null findings stay distinct from contradictions.**
- Every label stores its provenance: `direction_rule`, `direction_snippet`,
  `direction_method`, `direction_method_version`. The snippet is the exact
  sentence that triggered the rule, so a human can check it.

### Limitations (stated plainly)

The rules are **not validated against expert adjudication**, and no precision or
recall is claimed — none has been measured. They are a heuristic over abstract
text. Coverage is reported honestly: `classified`, `unclassified`, and
`classified_fraction` are returned, and the UI shows the caveat that
*unclassified sources are not evidence of consistency*. Where no rule matches,
the system returns `not_classified` rather than guessing.

### Contradiction counting

Each **study unit** counts at most once per direction, so repeated passages from
one PMID never inflate the tally. `conflicting_evidence_present` is true only
when two or more *different* classified directions coexist. No net
positive/negative score is computed — combining incompatible outcomes into one
number would be misleading.

## 7. API

`POST /api/query` is unchanged and backward compatible. Two additive fields:

- `results[].evidence_audit` — the per-candidate audit.
- `evidence_audit_summary` — query-level counts (`audited`, `complete`,
  `not_auditable`, `failed`) plus version and method identifiers.

```json
{
  "results": [
    {
      "rank": 1,
      "drug": "Galantamine",
      "evidence": { "score": 0.779, "tier": "Moderate", "support": 3 },
      "claims": [ "…" ],
      "evidence_audit": {
        "version": "1.0",
        "method": "leave_one_independent_study_out",
        "scoring_function": "retrieval.evidence_score:0.25R+0.35P+0.40Q",
        "status": "complete",
        "ranking_scope": "evidence_rank_over_retrieved_candidates",
        "baseline": { "evidence_score": 0.779, "evidence_rank": 1, "displayed_kg_rank": 1 },
        "study_counts": {
          "study_units": 3, "source_records": 3,
          "study_independence_verified": false,
          "supportive": 1, "not_classified": 2,
          "conflicting_evidence_present": false
        },
        "stability": {
          "status": "complete",
          "successful_counterfactuals": 3, "failed_counterfactuals": 0,
          "max_absolute_score_change": 0.355, "max_rank_movement": 2, "rank_range": 1
        },
        "counterfactuals": [ "…one entry per study unit…" ],
        "sources": [ "…source-level evidence ledger…" ],
        "warnings": [ "…" ]
      }
    }
  ],
  "evidence_audit_summary": {
    "version": "1.0", "status": "computed",
    "audited": 10, "complete": 3, "not_auditable": 7, "failed": 0
  }
}
```

**Cached results.** A cache entry that predates the audit returns
`evidence_audit_summary.status = "unavailable_for_cached_result"` and the UI shows
*"Audit unavailable for this cached result"*. A stale audit is never presented as
current and no audit is ever fabricated. The demo cache has been rebuilt so the
five demonstration diseases carry real audits.

**Security.** Source links are built only from PMIDs validated as digits
(`normalize_pmid`), so a link is never constructed from untrusted text. No local
paths, secrets, or infrastructure details are exposed.

## 8. Configuration and reproducibility

All versioned identifiers and thresholds live at the top of `src/audit.py`:

| Setting | Value |
|---|---|
| `AUDIT_VERSION` | `1.0` |
| `AUDIT_METHOD` | `leave_one_independent_study_out` |
| `SCORING_FUNCTION_ID` | `retrieval.evidence_score:0.25R+0.35P+0.40Q` |
| `DIRECTION_METHOD` / `_VERSION` | `lexical_rules` / `1.0` |
| `TIE_BREAK` | `score_desc_then_kg_order` |
| `STABILITY_CONFIG` | see §5 |

Same evidence + same config + same code version ⇒ identical audit. The audit
makes no generative calls, so there is no nondeterministic step.

## 10. Known limitations

1. **Cross-PMID study independence is unverifiable** with the current corpus —
   reported as `unknown`, never assumed.
2. **Direction labels are unvalidated heuristics.** Coverage is partial and
   reported; no accuracy claim is made.
3. **Support is passage-counted, not PMID-deduplicated** (see §2) — a deliberate,
   documented divergence from the specification.
4. **Corpus coverage is 113 of 23,224 diseases.** Uncovered diseases return
   candidates with zero evidence and abstain rather than inventing support.
5. **Reviews are units too.** They are flagged and warned about, but the strict
   sensitivity metric still treats them as removable units.
6. **No clinician adjudication.** No output has been reviewed by a qualified
   clinician.
7. **Single-source dominance is defined by an arbitrary, experimental threshold**
   (§5), not by an established statistical criterion.
